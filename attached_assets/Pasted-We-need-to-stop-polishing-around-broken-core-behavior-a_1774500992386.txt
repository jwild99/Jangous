================================
PRIORITY 2 — POOL BREAK SHOULD NOT RESET THE BALL
================================

In pool, every time I break, it resets the ball. That is wrong.

The break shot should:
- launch the cue ball
- collide with the rack
- leave the table state exactly where the physics result ends
- continue the game from that resulting table layout

It should NOT:
- reset the cue ball
- rerack or partially rerack balls
- restart the shot
- wipe the table state unless there is an intentional rule-based reset
- jump into some default placement flow after contact

Fix this immediately.

Investigate likely causes:
- break state is incorrectly triggering a new rack init after first shot
- turn transition after break is resetting game state
- foul/shot resolution logic is incorrectly calling resetRack() or resetCueBall()
- physics resolution after break is interpreted as invalid and forcing reset
- server/client state mismatch causes table re-sync to default layout
- “new turn” logic is rebuilding initial positions
- scratch handling is firing incorrectly on break
- break-complete logic is not separated from full game reset logic

Pool behavior must be:
- break happens once
- resulting table layout remains
- next turn continues from that exact layout
- only real rule-based events should reposition cue ball or change state

Run tests for:
- legal break with no scratch
- break where balls pocket
- break with scratch
- break with no pocket
- break against bot
- break against local/human
- rematch after completed game

Acceptance criteria for pool break:
- breaking no longer resets the table
- table remains in post-break state
- cue ball only repositions when an actual rule requires it
- no hidden rerack after break
