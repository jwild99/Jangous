1. Executive Implementation Summary
The current direction for Jango.US should be treated as a full product overhaul, not a small UI clean-up. The games need to feel more polished, the site needs to feel premium on mobile, and the entire user journey needs to support competitive play, fast entry, clear stakes, satisfying wins, and repeat play.
• Every game must be rebuilt or upgraded around feel first: input response, camera, physics clarity, hit feedback, sound, animations, UI, and end-of-match reward moments.
• Mobile must be first-class. No desktop-only layouts, tiny buttons, cramped menus, or screens that feel like they were squeezed down after the fact.
• The home page, profile, wallet, lobby, tournament creation, match result, leaderboard, and game screens must share one design system.
• Every game must have clear loading, pre-match, in-match, post-match, rematch, and cash-out flows.
• Performance must be treated like a feature. Lag, stutter, bad collisions, slow transitions, or delayed controls destroy trust when money or competitive value is involved.
• Do not send players to external windows for the core Tron game or any core first-party game. Games need to feel native to Jango.US.

2. Global Product Standard
2.1 Brand Feel
• Jango.US should feel like a dark competitive arcade, casino-quality lobby, and esports platform combined.
• The user should feel like every screen is part of one universe: black/charcoal base, electric accents, neon glow, subtle smoke/energy particles, glass panels, clean typography, and motion that feels expensive.

4. Mobile-First Requirements
4.1 Mobile Layout Rules
• Minimum tappable target: 44px height. Primary game controls should be 56px+ when possible.
• Do not use desktop tables on mobile. Convert leaderboards, match history, tournaments, and transaction lists into stacked cards.
• Keep the main CTA sticky on important flows: Join Match, Create Tournament, Confirm Entry, Start Game, Rematch.
• Avoid tiny close icons. Use large bottom sheets, clear back buttons, swipe-friendly menus, and reachable controls.
• Use safe-area padding for iPhone notches and bottom home indicators.
• Game canvases must adapt to portrait and landscape where appropriate. If a game requires landscape, show a polished rotate-device screen, not a broken layout.
• All modals should become bottom sheets on mobile unless full-screen is needed.
4.2 Mobile Game Controls
• Controls must be configurable where possible: left/right hand layout, opacity slider, size slider, haptic toggle, sound toggle.
• Virtual joystick must feel responsive, have dead-zone tuning, and not block important game visuals.
• Buttons need press animations, cooldown indicators, and clear disabled states.
• Prevent browser scrolling, pull-to-refresh, accidental zoom, and address bar jumps while in active game mode.
• Add reconnect overlay and pause/forfeit logic when app backgrounding or network drops.

5.2 Universal Match Ceremony
Before every paid or competitive match, create a short ceremonial animation that shows the stakes entering the pot. This is important for dopamine, trust, and competitive tension.
• Show both players locked in with avatars/usernames.
• Animate entry fees, tokens, coins, or “scalps” flying into a center pot.
• Show total pot with glow, pulse, and sound effect.
• Show rules reminder: game, stake, win condition, time limit, disconnect policy.
• Keep it short. Target 2-4 seconds with a skip option after the first few times.
6. Game-Specific Overhaul Requirements
6.x Tron / Lightcycle
• Embed fully inside Jango.US. No external window for core play. The player should never feel like they left the platform.
• Fix lag by optimizing render loop, using requestAnimationFrame correctly, reducing expensive DOM operations, pooling particles, and separating simulation tick from render tick.
• Upgrade visuals with glowing trails, bloom-like effects, grid floor, animated arena walls, boost sparks, crash explosion, and cinematic round intro.
• Add powerups: speed boost, shield, ghost phase, trail bomb, trail cut, EMP pulse, reverse controls trap, mini-map reveal, and slow-time pickup. Balance for fairness.
• Add polished HUD: player panels, score, timer, powerup slots, cooldown rings, connection/ping, stake/pot, and round number.
• Fix collision consistency. Player should clearly understand why they crashed. Add crash marker and instant replay micro-camera if possible.
• Add mobile controls: swipe steering, virtual directional pad, or tap-left/tap-right mode. Let users choose.
• Add arena variants: classic grid, neon city, lava core, ice wireframe, tournament arena.
6.x Pool / Billiards
• Improve physics consistency: accurate ball collision, spin, friction, cushion bounce, pocket detection, and foul logic.
• Add premium aiming UI: cue line, ghost ball preview, power meter, spin control, and subtle assist based on game mode.
• Mobile must support drag-to-aim, pull-back power, tap fine-tune, and visible cue angle without fingers blocking the target.
• Add camera polish: smooth table zoom, follow cue ball after shot, cinematic pocket cam on big shots, no jitter.
• Add match overlays: turn indicator, remaining balls, foul warning, timer, score, stake/pot, player cards.
• Add satisfying ball sounds, felt friction, pocket drop, cue strike, crowd/room ambience optional.
• Add practice drills and skill challenges for retention.
6.x Bowling
• Create a polished lane environment with reflective lane, animated pins, crowd/arcade ambience, neon signage, and branded lane screens.
• Add throw mechanics with power, angle, curve/spin, and timing. On mobile, use swipe velocity and curve gesture.
• Pin physics must feel believable. Avoid pins sliding strangely or falling late in a broken way.
• Add camera sequence: approach, release, lane follow, pin impact, slow-motion strike/spare highlight.
• HUD should show frame, pins left, scorecard, current player, stake/pot, timer, and throw feedback.
• Add dopamine moments: strike explosion, spare sparkle, turkey animation, perfect game celebration.
6.x Racing
• Fix finish-line/lap detection so cars cannot miss lap registration. Use checkpoint gates and ordered checkpoint validation, not only a finish-line collision.
• Improve graphics: better road material, lighting, motion blur feel, tire marks, sparks, speed lines, dynamic camera shake, polished car models or sprites.
• Add mobile controls: tilt steering optional, left/right buttons, brake/boost buttons, configurable layout.
• Add race HUD: speed, lap, position, mini-map, boost, damage/status, countdown, stake/pot.
• Add collision and respawn rules that feel fair. Prevent exploit loops around the finish line.
• Add track variants and hazards: boost pads, oil slicks, shortcuts, jumps, gates, and moving obstacles.
6.x Arcade / Future Games
• Every new game must pass the same Game Feel Checklist before release.
• Each game needs practice mode, paid match mode, tournament mode, replay/proof data, mobile controls, and end-screen stats.
• Prototype games are allowed internally, but never ship raw prototypes to users or investors.

10.1 Game Engine / Architecture Direction
• Create a shared GameShell component used by every game: loading, countdown, HUD, pause menu, result screen, reconnect overlay, and analytics hooks.
• Create shared UI components: Button, Modal/BottomSheet, GameCard, PlayerCard, StakePot, LeaderboardCard, TournamentWizard, Toast, Tooltip, EmptyState, ErrorState.
• Separate game simulation from React UI where possible. React should not re-render constantly during gameplay.
• Use canvas/WebGL or a game framework where appropriate for smoother graphics. Avoid building high-action games with too many moving DOM elements.
• Add feature flags for effects quality: Low, Medium, High, Ultra. Auto-detect device performance and allow manual override.
11. Wallet, Stakes, Fees, and Trust
Because Jango.US includes competitive value and payments, the UX needs to be transparent, secure, and trustworthy. Every fee, stake, payout, and result must be clear before and after a match.
• Before entry, show entry amount, total pot, platform fee if applicable, expected prize/payout, and refund/disconnect rules.
• After match, show result, prize won/lost, updated balance, transaction ID, and match ID.
• Never hide fees in small text. Make it clean and professional.
• Add pending state for withdrawals/deposits and clear support route if something is delayed.
• Add security states: verify email, 2FA prompt, suspicious login alert, wallet confirmation.

17. Final Notes for Developer
The priority is polish, trust, and retention. Jango.US should not feel like a collection of separate mini-games. It should feel like one competitive gaming ecosystem where games, stakes, profiles, leaderboards, tournaments, and story all connect. Every interaction should look intentional. Every match should feel exciting. Every mobile screen should feel designed, not squeezed. Every game should feel fair, fast, and rewarding.
