STATE MANAGEMENT (ZUSTAND)
--------------------------------------------------

Create stores:

useUserStore:
- user
- balance
- rank
- xp
- level

useMatchStore:
- currentMatch
- matchState
- queueState

useUIStore:
- modals
- notifications
- loading states

useLiveStore:
- liveFeed
- tickerData

RULE:
Never mutate balance locally.
Balance only updates from API or websocket.

--------------------------------------------------
UI STATE HANDLING
--------------------------------------------------

Each interactive component must support:

- idle
- hover
- active
- loading
- success
- error

Example (button):
- idle → normal
- hover → glow
- active → scale down
- loading → spinner
- success → checkmark flash
- error → shake + red glow

==================================================
SECTION 18: MATCHMAKING ENGINE (REDIS)
==================================================

Use Redis queues:

Queue key:
match:{game}:{stake}

Flow:
- user enters queue
- system matches 2 players
- create match record
- emit websocket event

Timeout:
- remove user after X seconds
