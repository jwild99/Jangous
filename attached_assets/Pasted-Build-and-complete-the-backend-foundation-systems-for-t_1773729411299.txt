Build and complete the backend/foundation systems for the platform so all major features work reliably, securely, and scale correctly across desktop and mobile. Focus on architecture, logic, performance, and data integrity more than UI. This work should make the platform feel production-ready behind the scenes.

CORE GOAL:
Create the backend systems that power matches, wagers, wallets, rankings, messaging, tournaments, clans, challenges, anti-cheat, reputation, reconnect logic, logging, and analytics. Everything should be structured cleanly so future features can plug into it without rewriting the core.

1. SERVER-AUTHORITATIVE MATCH ENGINE
Build a centralized match engine that acts as the single source of truth for every game session.
Requirements:
- Server-authoritative state for all games
- Never trust the client for outcomes, move validation, timers, or payouts
- Each match should have:
  - unique match ID
  - game type
  - player IDs
  - match status (waiting, accepted, active, paused, reconnecting, completed, canceled, disputed)
  - timestamps for created, started, ended
- Real-time syncing through WebSockets or equivalent
- Support multiple matches running at the same time without collisions
- Match lifecycle management:
  - create match
  - invite/join
  - accept wager
  - lock funds
  - start match
  - track state updates
  - determine winner
  - finalize payout
  - archive results
- Add reconnect support so disconnected players can rejoin an active match
- Add timeout/forfeit handling if a player fails to return
- Ensure matches recover safely after temporary server or socket issues

2. WALLET SYSTEM + TRANSACTION LEDGER
Build a secure wallet system using Scalps as the platform currency.
Requirements:
- Every user has a wallet balance
- Every balance change must create a ledger entry
- Ledger must include:
  - transaction ID
  - user ID
  - transaction type (deposit, conversion, wager lock, payout, refund, reward, item purchase, adjustment)
  - amount
  - balance before
  - balance after
  - timestamp
  - related match ID or event ID if applicable
  - status (pending, completed, failed, reversed)
- Make all financial actions atomic and idempotent
- Prevent double spending
- Prevent duplicate payouts
- Add rollback/reversal support for failed or interrupted financial flows
- Make sure balance is always derived safely and consistently
- Lock wallet funds when a wager is accepted and release or settle them correctly after result resolution
- Keep all wallet logic server-side only

3. WAGER ENGINE + PAYOUT LOGIC
Create a wager engine that handles player-vs-player stakes safely.
Requirements:
- Both players must explicitly accept before a wagered match begins
- Validate both players have enough balance
- Lock wager funds before match start
- Only start the match after both wager locks succeed
- On completion:
  - validate the official winner from the match engine
  - settle payout automatically
  - support house fee/rake as configurable if needed later
- Handle edge cases:
  - draw = refund both players
  - disconnect with no return = auto-forfeit
  - server interruption mid-match = safe recovery state
  - canceled before start = unlock funds
  - disputed result = hold payout until resolved
- Create a clean service layer so this logic can be reused across all games

4. RANKING SYSTEM (R6 STYLE HYBRID)
Build a ranking/MMR system inspired by Rainbow Six Siege.
Requirements:

- Visible rank points
- Rank tiers such as Bronze, Silver, Gold, Platinum, Diamond, Champion
- Champion should show exact leaderboard placement
- Rank #1 should receive a special GOAT status/title
- MMR gain/loss should depend on:

  - possible streak tuning if desired
- Store:

  - current MMR
  - season stats
  - rank history
  - highest rank achieved
- Build for seasonal resets later
- Matchmaking should use hidden MMR, not just visible rank badge
- Keep ranking updates secure and server-calculated only

5. MATCHMAKING SYSTEM
Build a robust matchmaking backend.

- Gradually widen acceptable matchmaking criteria if queue time grows
- Keep matchmaking extensible for future clan battles and private lobbies
- Prevent abusive rematch farming in ranked if needed

6. ANTI-RAGE QUIT / RECONNECT SYSTEM
Build a reconnect and anti-rage quit system that protects match integrity.
Requirements:
- If a player disconnects during a live match:
  - flag the match as reconnecting
  - pause where appropriate depending on game type
  - start a visible reconnect timer on backend, default 5 minutes
- If player returns in time:
  - restore them into the live match
  - sync state safely
- If they do not return:
  - count as forfeit
  - award win to the opponent
  - settle wager automatically
- Track repeated disconnect behavior
- Add escalating penalties:
  - warning
  - temporary matchmaking cooldown
  - increased rank loss
  - reputation penalty
- Make system smart enough to distinguish occasional connection problems from abuse when possible
