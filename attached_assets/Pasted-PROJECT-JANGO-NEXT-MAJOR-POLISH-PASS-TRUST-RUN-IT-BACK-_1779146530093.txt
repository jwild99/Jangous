PROJECT: JANGO NEXT MAJOR POLISH PASS — TRUST, RUN-IT-BACK, TOURNAMENTS, DEPTH, SOUND/HAPTICS, CLEANUP

GOAL:
Upgrade Jango so the platform feels more trustworthy, more polished, more alive, more competitive, and more production-ready.

Focus areas:
1. Trust gap / money clarity
2. Run-it-back match loop
3. Tournament system overhaul, especially polished brackets
4. Visual depth / less flat UI
5. Sound + haptics
6. Remove confusing or unfinished features

This needs to be implemented with real UI states, backend logic, animations, responsive behavior, and QA checks.

==================================================
SECTION 1: TRUST GAP / MONEY CLARITY
==================================================

This platform uses Scalps, wagers, deposits, prize pools, and payouts. Users must always understand:
- how much they are risking
- how much they can win
- what fees/rake apply
- when funds move
- why their balance changed
- whether an action is secure/verified

--------------------------------------------------

--------------------------------------------------

Modal title:
“Confirm Match Entry”

Modal content:
- Game name
- Match type:
  Casual / Ranked / Tournament / Practice
- Opponent:
  username, bot name, or “Waiting for opponent”
- Required wager:
  “Entry: X Scalps”
- Total pot:
  “Total Pot: X Scalps”
- Platform fee:
  “Platform Fee: 3%”
- Winner receives:
  “Winner Receives: X Scalps”
- User current balance
- User balance after entry

Example layout:
Required Wager: 5 Scalps
Your Balance: 20 Scalps
Total Pot: 10 Scalps
Platform Fee: 3%
Winner Receives: 9.70 Scalps
Balance After Joining: 15 Scalps

Button:
“Confirm & Join”

Secondary:
“Cancel”

Rules:
- If match is free, title it “Free Practice Match”
- Do not show confusing 0 Scalp wager text
- If user has insufficient funds, do not open confirm modal
- Instead show Add Funds prompt

--------------------------------------------------

  “Find Similar Match”

--------------------------------------------------
3.2 TOURNAMENT JOIN FLOW
--------------------------------------------------

On clicking Enter Tournament:

Step 1:
Open confirmation modal.

Step 2:
Backend validates:
- user is logged in
- user has enough balance
- tournament is open
- tournament is not full
- user is not already entered
- user meets requirements
- user is not banned/restricted

Step 3:
If valid, backend transaction:
- deduct entry fee
- create transaction record
- add user to tournament_entries
- increment prize pool
- assign bracket seed/slot
- emit tournament_update websocket event

This must be atomic.
No partial state.
No double entry.
No race conditions.

Step 4:
Frontend success:
- “You’re In”
- balance count-down
- prize pool count-up
- bracket opens
- current user highlighted

Failure cases:
Insufficient funds:
“You need X more Scalps to enter.”

Tournament full:
“This tournament just filled.”

Already entered:
“You’re already in this tournament.”

Closed:
“Entry has closed.”

  “Ready”

3.10 TOURNAMENT EDGE CASES
--------------------------------------------------

Handle:

Tournament fills while user joins:
- no deduction
- show “Tournament filled”

User refreshes:
- tournament state reloads correctly

User disconnects:
- tournament entry remains
- rules determine forfeit if match not joined in time

Odd number of players:
- use BYE slots
- highest seeds get bye if seeding exists

Duplicate click on join:
- button loading/disabled
- backend idempotency prevents double entry

Prize pool mismatch:
- recalculate from entries server-side
- admin alert if mismatch

SECTION 5: SOUND + HAPTICS
==================================================

Add sound and haptic feedback without making the app annoying.

--------------------------------------------------

--------------------------------------------------

Create one centralized system:

Feedback.play(eventName)
Feedback.haptic(patternName)

Do not hardcode audio calls across random components.

User settings:
- sound on/off
- haptics on/off
- volume slider
- reduce motion/effects toggle

Persist settings in:
- user settings if logged in
- localStorage fallback

[10]

[20]

[20, 40, 20]

[50, 30, 50]

big win:
[40, 30, 40, 30, 80]
