We need to fix and fully rebuild the deposit/payment system for Jango. Right now the system is insecure and allows users to credit themselves without paying. This must be treated as a critical production issue.

========================
CRITICAL ISSUE #1 – FREE MONEY EXPLOIT
========================

Right now, when a user generates a crypto deposit address, there is a button that says “I’ve sent the funds.” If the user clicks it, their balance is credited instantly even if no crypto was sent.

THIS IS A CRITICAL SECURITY VULNERABILITY.

Fix immediately:

- Remove ANY logic where frontend actions can credit balance
- The frontend must NEVER trigger balance updates
- Clicking “I’ve sent funds” should NOT affect balance in any way
- At most, it can update UI state only (optional)

STRICT RULE:
User balance must ONLY update from verified backend payment confirmations.

========================
CRITICAL ISSUE #2 – CRYPTO DEPOSITS NOT VERIFIED
========================

Rebuild crypto deposit flow properly:

Flow:
1. User clicks “Generate Deposit Address”
2. Backend:
   - Creates deposit record (status = pending)
   - Requests real deposit address from crypto provider
3. Frontend displays:
   - Wallet address
   - QR code
   - Network warning
4. User sends crypto externally
5. Backend listens for provider webhook / blockchain confirmation
6. Only after confirmation:
   - Mark deposit = confirmed
   - Credit user balance

Deposit statuses:
- pending
- awaiting_confirmation
- confirmed
- failed
- expired

Do NOT credit users:
- when address is generated
- when user clicks anything
- when transaction is unconfirmed

========================
CRITICAL ISSUE #3 – REMOVE ALL FAKE CREDIT LOGIC

Audit and REMOVE:
- Any addBalance() calls from frontend
- Any dev/test shortcuts that auto-credit users
- Any “mock payment success” logic still active

Balance updates must:
- Happen ONLY on backend

- Be idempotent (no double crediting)
